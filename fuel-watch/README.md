# Fuel Watch skill

## Сборка и установка

Репозиторий — единственное место, где нужны `npm` и `node_modules`. Перед публикацией skill выполняется:

```bash
npm ci --ignore-scripts
npm run build
npm test
npm run test:dist
```

Hermes должен синхронизировать весь каталог skill вместе с committed `dist/`. На целевой машине Fuel Watch запускается только через `dist/scripts/*.mjs`; `npm install` там не нужен и запрещён инструкцией skill. Внешняя команда `agent-browser` остаётся отдельным runtime prerequisite и никогда не устанавливается самим skill.

## Постоянные данные

Установленный каталог skill считается read-only и полностью заменяемым. Все изменяемые данные находятся вне него:

- `~/.fuel-watch/config/config.json` — пользовательские настройки, создаются из шаблона только при первом запуске;
- `~/.fuel-watch/config/agent-browser.json` — пользовательский browser config;
- `~/.fuel-watch/history/history.json` — компактная 7-дневная история;
- `~/.fuel-watch/state/latest.json` — последний snapshot, continuity идентичности и coverage-baselines;
- `~/.fuel-watch/monitors/<id>/` — транзакционное состояние активных мониторов.

Повторная синхронизация skill не перезаписывает эти файлы. Для изолированного окружения весь корень можно изменить переменной `FUEL_WATCH_HOME`; отдельно путь истории — `FUEL_WATCH_HISTORY_PATH`.

При первом запуске существующая история из прежнего default path `~/.local/state/fuel-watch/history.json` (или `$XDG_STATE_HOME/fuel-watch/history.json`) копируется в новый каталог без удаления оригинала и только если новая история ещё не создана.

`monitoring.intervalMinutes` — пользовательская настройка (5–1440 минут), а не часть immutable skill-пакета.

## Полевые сверки

Наблюдения ниже — разовые проверки, а не долговременный рейтинг источников.

- 31 августа 2026, Рокоссовского, 1Р: реальное возобновление продажи 92/95 примерно в 12:20–12:40 после прибытия бензовоза около 11:30. Лучше всего событие отразил Benzonavt (включая доступную человеку историю), затем gdebenz; 2GIS был полезен как дополнительный текущий сигнал, Yandex хуже всего подходил для временной сверки из-за отсутствия grade-specific freshness metadata.

Новые ручные сверки следует добавлять отдельными датированными пунктами с фактическим состоянием, временем проверки и показаниями всех источников.

## Что источники публикуют помимо наличия

Живая проверка контрактов 21 сентября 2026 года на всех четырёх источниках:

- **Каталог марок станции.** `station.fuel_assortment` у 2GIS, `fuels` у Benzonavt, `meta.f` у gdebenz (заполнен не у всех строк). Yandex каталог не публикует: его `fuelAvailability` описывает марки, по которым есть данные о наличии, а не ассортимент, поэтому выводить каталог из него нельзя. В живом прогоне каталог был известен у 30 АЗС из 74; отсутствие каталога трактуется как «неизвестно», а не «не продают».
- **Лимиты литров.** `fuel_statuses[].limit_liters` и станционный `limit_liters` у 2GIS, `limits[]` (марка, литры, `since`) в detail-ответе Benzonavt, текст `Лимит N л` в карточке gdebenz. В отчёте показывается минимальный известный лимит на АИ-95 среди наблюдений, которые ещё не истекли по общему окну свежести; лимит с известным и уже не свежим временем печатается вместе с возрастом. Источник, который вообще не датирует лимиты (2GIS), публикует их рядом с текущим статусом, поэтому возраст у них не выдумывается.
- **Метрики доверия источника.** `confidence_base`/`confirmations`/`svc` и поля автора комментария у gdebenz, `st.confidence`/`confirmations`/`reports`/`basis` и `reports_24h` у Benzonavt, `reports_count` у 2GIS. Сохраняются как provenance в поле `trust`; в уверенность Fuel Watch не переводятся.
- **`status_history` Benzonavt не подходит для 7-дневной истории.** Проверено на пяти станциях: ответ всегда содержит ровно два дня с посуточной гранулярностью (`day`, `status`, `confidence`, `fuels_now`) и без времени суток, а `reports_24h` — просто счётчик. Прогнозу нужно типичное местное время возобновления, которого там нет, поэтому эти поля не используются как источник истории.
- **`closed`/`closed_by_schedule` у 2GIS** осознанно не используются: интересует наличие 95-го, а не режим работы.

## Разбор противоречий внутри одного источника

У gdebenz видимый текст карточки и скрытое поле `fuels_now` перечисляют марки независимо и могут расходиться: 21 сентября 2026 года это было у 3 строк из 104 (например, `ул Глубокоовражная, 25` — карточка `92, ДТ · Очередь ≈5–20 машин` против `fuels_now = 92,95,ДТ`). Раньше адаптер объединял оба списка и получал ложный текущий сигнал АИ-95. Теперь марка, названная только одной стороной, даёт `UNCERTAIN` со структурным конфликтом (`kind: VISIBLE_VS_HIDDEN`, обе исходные формулировки сохраняются), и такой позитив не попадает в «Куда ехать». Прямой позитив другого источника по той же АЗС при этом остаётся в силе — конфликт локален для источника, который себе противоречит.

## Уверенность

`низкая`, `средняя` и `высокая` — это уверенность Fuel Watch в собственной оценке, а не заявленная источником вероятность. Она вычисляется из типа и свежести свидетельства, независимости provenance-групп, числа свежих прямых подтверждений и grade-specific активности. Адаптеры сохраняют доступные timestamps, конфликты и счётчики сигналов, но сейчас ни один из четырёх источников не даёт проверенного универсального confidence-поля с понятной и сопоставимой семантикой. Если такое поле появится, сначала нужно сохранить его как provenance и проверить калибровку; автоматически подменять им итоговую уверенность нельзя.
