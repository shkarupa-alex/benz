# Fuel Watch — пожелания и технический долг

Это живой список только незавершённых пожеланий и технического долга. Выполненные пункты удаляем: их история остаётся в Git.

## Пожелания

- [ ] **P1 — «Разговорчики» Яндекс Карт как исторический источник.** Не реализовывать, пока не получен реальный образец события. Повторная проверка 21 сентября 2026 года: `https://yandex.ru/maps/api/traffic/events` и `.../api/roadEvents` на неподписанный запрос отдают только заглушку `{"csrfToken": …}`, а `core-jams-rdr-cache.maps.yandex.net/1.1/trfe` из страницы не достаётся вовсе. Получить образец теперь означало бы воспроизводить подписанные запросы самой страницы — для гипотетической фичи это преждевременно. Когда данные станут видны, сохранить без потерь весь массив сообщений каждого события (исходный текст, порядок, времена, event/thread/message ID, координаты и доступные подтверждения), передавать агенту этот массив **как есть** как недоверенные данные и отдельно строить производные классификации. Хранить сообщения в истории, чтобы находить упоминания приезда бензовоза, начала продаж и очередей и использовать их при прогнозировании типичного времени подвоза/возобновления продаж. До реализации на живом образце проверить контракт получения сообщений и разработать fail-closed привязку события к АЗС: точный organization ID, либо уникальная пространственно-текстовая привязка; неоднозначные события не должны менять вердикт конкретной станции. Отсутствие/недоступность «Разговорчиков» не считать отсутствием бензина и не ухудшать здоровье основного Yandex-источника.

## Источники

- [ ] **Yandex перестал отдавать наличие топлива в веб-выдаче.** 13 октября 2026 года (во время масштабного сбоя сервисов Яндекса) `script.state-view` поиска «АЗС АИ-95» не содержит `fuelAvailability`/`signalsCountPerHour`, а в конфиге страницы стоит `gasStationFuelInfoDisabled: true`; у 15 организаций остался только `fuelInfo` с ценами MultiGo (без наличия). Адаптер честно отдаёт `PARTIAL/LOW_FUEL_COVERAGE`, но его DOM-fallback по `[data-id]` подбирает карточки без координат (в одном из прошлых snapshot туда попали остановки транспорта). Перепроверить после восстановления сервисов: если флаг останется, отключить Yandex как источник наличия, а DOM-fallback ограничить карточками организаций.

- [ ] **Третье состояние для нечитаемого списка марок в карточке gdebenz.** Сейчас сегмент карточки считается перечислением марок, только если *все* его токены — топливные; иначе он молчит. Это строго безопаснее прежнего denylist (прозу вида «Обновлено 95 минут назад» больше не читаем как АИ-95), но сегмент с топливом и прозой в одной строке («Только 92», «95 — есть») тоже читается как «ничего не перечислено» и потому не спорит с `fuels_now`. В наблюдённом корпусе таких строк нет, единственная известная — `ДТ — нет топлива`, где решение всё равно принимает `familyUnavailable`. Полностью консервативный вариант: третье состояние «видимая сторона нечитаема», которое блокирует позитив, известный только из скрытого поля, вместо того чтобы его пропускать.

## Browser runtime

- [ ] **Запоминать последний pid демона namespace, а не первый.** `rememberDaemonPid` из-за `has()`-короткого замыкания фиксирует первый увиденный pid. Если демон перезапустится внутри того же namespace до закрытия (`AGENT_BROWSER_IDLE_TIMEOUT_MS` 10 с против adapter timeout 45 с — сценарий правдоподобный), pid в файле перестанет совпадать с наблюдённым, и осиротевший процесс не будет ни показан, ни прибит. Направление безопасное (чужой процесс не убиваем), это потерянный backstop, а не утечка: демон, который однажды ушёл по idle, уйдёт по idle и снова. Чинится семантикой «храним последний».

- [ ] **Убрать visual-mode workaround после исправления agent-browser.** Проверено на 0.38.1 (21 сентября 2026 года): сбой CDP network controls продолжал возникать на части источников. 13 октября 2026 года на 0.38.2 стало хуже: с `--allowed-domains` (даже `'*'`) gdebenz и 2GIS через ~2 с после успешного `open` становятся `about:blank`, без флага те же страницы грузятся; example.com при этом работает. (`ERR_CONNECTION_REFUSED` у benzonavt в тот же день к controls не относится: после ~10 живых прогонов за час его 80/443 отклоняли соединения с нашего IP и для curl, хотя хост отвечал на ping и SSH.) Collect теперь откатывается без controls по исходу, а не по тексту ошибки, поэтому на 0.38.2 практически все источники идут с `BROWSER_NETWORK_CONTROLS_DEGRADED`. Видимый осмотр по-прежнему использует точные URL без network controls с ручной fail-closed проверкой final host.

- [ ] **2GIS отвечает agent-browser входом через Сбер ID.** 13 октября 2026 года headed-сессия agent-browser стабильно попадает на `id.sber.ru/…/authorize.do?…machineClick=aggressivelogin&redirect_uri=https://2gis.ru/_/auth/sberid/code`, headless — на `captcha.2gis.ru`; обычный браузер с того же IP получает страницу. Теперь это честный `CHALLENGE`, а не `RESOURCE_BLOCKED`. Обходить нельзя; если не пройдёт само, 2GIS как источник нужно пересмотреть.
