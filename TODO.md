# Fuel Watch — пожелания и технический долг

Это живой список пожеланий. Новые идеи добавляем сюда до проектирования; подтверждённые дефекты закрываем кодом и отмечаем выполненными.

## Пожелания

- [ ] **P0 — User-in-the-loop CAPTCHA.** Продумать безопасный сценарий, в котором skill обнаруживает CAPTCHA, показывает пользователю страницу или снимок в интерфейсе чата, ждёт ручного решения и продолжает ту же browser-сессию. Автоматический обход CAPTCHA не закладывать; отдельно проверить, допускает ли интерфейс передачу управления вкладкой пользователю и как ограничить время ожидания, повторные попытки и утечку сессии.
- [x] **P1 — История поставок и прогноз.** Реализована компактная история за последние 7 дней. Настоящий per-grade rolling-count бензиновых сигналов имеет наивысший приоритет, но живой Yandex отдаёт только агрегатный station-level счётчик, потенциально включающий дизель, поэтому он не используется. Текущий основной признак общего подвоза — типичное время синхронных переходов статусов бензиновых марок 92/95/98/100; дизель, газ и неизвестные продукты исключены. Union-переходы АИ-95 используются как fallback. И разовые проверки, и monitoring tick’и накапливают данные. Отчёт даёт до трёх прогнозов с интервалом, типом сигнала, основой, выборкой и уверенностью либо честный cold-start.
- [ ] **P2 — Разовая произвольная география.** Поддержать выбор целого населённого пункта или коридора вдоль маршрута через указанные города. Это не новый default: зона создаётся только для конкретного запуска, имеет явные границы/ширину коридора, лимиты площади и числа станций и не перезаписывает основной многогранник.
- [x] **Новый источник — benzonavt.ru.** Подключён browser-mediated `/api/v1/stations?bbox=…`: устойчивый station ID, координаты, точные текущие марки топлива, family-wide негативы, очередь и timestamp. Источник включён в `crowd-shared`, чтобы коррелирующие данные не завышали уверенность.

## Открытые продуктовые решения

- [ ] **Отсекать перекрытые `st.conflict` Benzonavt.** Проверить на более длинной живой выборке семантику `conflict.created_at` относительно `st.updated_at`. Если оба source timestamp валидны и конфликт строго старше текущего статуса, считать его перекрытым; при новом, равном, неизвестном или некорректном времени сохранять `UNCERTAIN`. Добавить тесты clock skew и обеих направленностей yes/no до ослабления текущего fail-closed правила.
- [ ] В строке `95+` сохранять консервативный агрегат, но отдельно перечислять подтверждённые негативы по вариантам, чтобы факт `Экто: НЕТ` не терялся среди вариантов без свежих данных.
- [ ] Уменьшить стоимость browser polling: сейчас проверка готовности создаёт несколько CLI-процессов на итерацию. Исследовать один атомарный `eval` для URL, title, текста и selector readiness без ослабления проверки page drift.

## Browser runtime

- [ ] **Yandex map canvas.** В headed-режиме левая панель и структурированные `fuelAvailability` данные загружаются, но canvas карты визуально оставался пустым. После согласованного restart diagnostic daemon собрать короткими командами console errors и failed/blocked requests без `screenshot`, HAR или trace; проверить asset-domain allowlist отдельно от парсера.
- [ ] **Убрать visual-mode workaround после исправления agent-browser.** В версии 0.35.1 CDP network controls детерминированно ломают третью вкладку (`Cannot find default execution context`), а `screenshot` может заблокировать command queue. Сейчас видимый осмотр использует точные URL без network controls с ручной fail-closed проверкой final host; автоматический collect сохраняет allowlist.
- [x] **Freshness ГдеБЕНЗ.** Адаптер читает first-party `/api/nearby`, где доступны координаты и `last_at`; DOM остаётся fail-closed fallback. Если API перестаёт отдавать время, источник честно возвращается к `NO_FRESHNESS_METADATA`, не подставляя fetch time.

## Исправления из ревью

- [x] Cleanup принимает только принадлежащий Fuel Watch каталог внутри временного корня и валидирует ownership/state/lease перед рекурсивным удалением.
- [x] Ranking и список supporting sources учитывают только свежие текущие положительные свидетельства, исключая `CATALOG_ONLY` и expired.
- [x] Нарушение completeness invariants переводит источник в `PARTIAL` и запрещает обновлять baseline.
- [x] `LIKELY_AVAILABLE / LOW` сохраняется как осторожный `FIRST_SEEN`, без утверждения о фактическом появлении топлива.
- [x] Первичный redirect разрешён на любой host из `allowedDomains`; последующий page drift по-прежнему проверяется по строгому origin.
